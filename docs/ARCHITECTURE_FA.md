# تصمیمات معماری کارتونیا

## اطلاعات پروژهٔ استخراج‌شده

| مورد | تصمیم فعلی |
|---|---|
| نام و موضوع | کارتونیا؛ کاتالوگ و پخش انیمیشن/کارتون کودک |
| مخاطب | کودکان همراه والدین فارسی‌زبان؛ انتشار Android در کافه‌بازار/گوگل‌پلی |
| فریم‌ورک | Flutter + Material 3 + Riverpod |
| حس‌وحال | گرم، نرم، شاد و آرام؛ رنگ‌های نارنجی، آبی و طلایی |
| حساب کاربری | فعلاً ندارد؛ برای کاهش دادهٔ کودک و پیچیدگی امنیتی |
| مونتایزیشن | فعلاً ندارد؛ بنابراین Poolakey و paywall عمداً اضافه نشده‌اند |
| دادهٔ محتوا | کاتالوگ محلی قابل جایگزینی با API/CMS |

فایل Master Prompt به‌دلیل خالی بودن بخش «اطلاعات پروژه»، با توجه به `README` و کد قبلی پروژه تطبیق داده شده است. مواردی مثل پرداخت، ورود و cloud sync تا وقتی نیاز محصول مشخص نشده‌اند، پیاده‌سازی نشده‌اند تا حریم خصوصی کودک و حجم اپ بی‌دلیل آسیب نبیند.

## لایه‌ها و وابستگی‌ها

```text
Presentation (pages/widgets)
         ↓ Riverpod providers
Domain (CartoonRepository contract)
         ↓
Data (LocalCartoonRepository + models)
         ↓
Core (AppPreferences, theme, utilities)
```

- صفحه‌ها مستقیماً به `SharedPreferences` یا منبع کاتالوگ متصل نیستند.
- `AppPreferences` تنها محل نگه‌داری preferenceهای غیرحساس است.
- `cartoonRepositoryProvider` محل composition برای تغییر از منبع محلی به REST/GraphQL/Firebase است.
- اطلاعات ویدئو در `EpisodeModel` است؛ پخش‌کننده فقط یک URL HTTPS می‌گیرد.

## چرا این انتخاب‌ها؟

### Riverpod
از قبل Riverpod در پروژه بوده و برای stateهای کوچک، قابل‌آزمون و مستقل از Widget مناسب است. stateهای persistence شامل علاقه‌مندی‌ها، تم، نام والد، autoplay و history هستند.

### SharedPreferences به‌جای Database
نسخهٔ فعلی فقط چند شناسه و درصد پیشرفت ذخیره می‌کند؛ SQLite/Hive در این مرحله پیچیدگی غیرضروری بود. با بزرگ‌شدن آفلاین‌کاتالوگ یا downloadها، migration به database لایهٔ data انجام می‌شود، بدون تغییر UI.

### تصویرسازی برداری به‌جای تصویر تصادفی شبکه
تصاویر تصادفی برای اپ کودک قابل‌کنترل نیستند، روی اینترنت ضعیف تجربه را خراب می‌کنند و ممکن است از نظر حقوقی/کیفی مناسب نباشند. `CartoonArtwork` یک artwork سبک، responsive و بدون asset شبکه است. برای انتشار تجاری می‌توان آن را با assetهای دارای مجوز یا URLهای CDN جایگزین کرد.

### عدم ورود و عدم پرداخت در نسخهٔ فعلی
برای مخاطب کودک، جمع‌آوری حساب و داده باید حداقلی باشد. تا زمانی که نیاز تجاری تأیید نشده، ورود، analytics و SDK پرداخت اضافه نشده‌اند. اگر پرداخت اضافه شد، باید در یک feature جدا، با Parental Gate و تست چرخه‌های خطا پیاده‌سازی شود.

## Design System

- **Primary:** `#FF8A50` — گرم و کودکانه، بدون شدت زننده
- **Secondary:** `#4DB9EE` — حس اعتماد و آسمان
- **Accent:** زرد، صورتی، سبز و بنفش فقط برای سلسله‌مراتب و بازخورد
- **Typography:** Vazirmatn از `google_fonts`
- **Radius:** 12 / 18 / 24 / 32
- **Spacing:** 4 / 8 / 16 / 24 / 32
- **Motion:** ease-out کوتاه، هالهٔ طلایی ۲٫۴ ثانیه‌ای و feedback لمسی سبک
- **Dark mode:** از `ThemeMode` و ColorScheme واقعی استفاده می‌کند؛ خنثی‌ها از Theme خوانده می‌شوند، نه رنگ‌های ثابت

## امنیت و حریم خصوصی

1. keystore و `key.properties` از Git خارج شده‌اند.
2. `usesCleartextTraffic` و Scoped Storage قدیمی حذف شده‌اند؛ تنها permission لازم `INTERNET` است.
3. قفل والدین PIN ثابت ندارد و با مسئلهٔ تصادفی باز می‌شود.
4. URLهای ویدئو باید HTTPS باشند. هنگام اتصال API، token فقط در secure storage نگه‌داری شود، نه SharedPreferences.
5. پیام خطای player جزئیات فنی یا URL را به کاربر نمایش نمی‌دهد.

## مرزهای فعلی نسخهٔ ۱.۱.۰

- URL نمونهٔ Flutter فقط برای اعتبارسنجی فنی player است و محتوای نهایی محصول نیست.
- backend، دانلود آفلاین، notification، پرداخت و analytics هنوز در Scope تأییدشده نیستند.
- build/analyze باید در محیط دارای Flutter انجام شود؛ در محیط agent فعلی Flutter SDK نصب نبود.
